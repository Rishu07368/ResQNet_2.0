Why max-flow?

The simulator links an artificial source to zone demand, uses directed road capacities for intermediate edges, and connects shelter locations to an artificial sink using intake capacity. Edmonds–Karp repeatedly finds a residual augmenting path and reports a minimum cut. Travel-time weights are never used as capacities.

This is a configurable academic simulation, not a guarantee of real-world evacuation safety.

ANALYSIS & DESIGN OF ALGORITHMS

About ResQNet

A reproducible, offline-friendly emergency response network simulation for learning graph algorithms.

⌗

Graph model

Metroville locations are vertices. Each directed road is an edge with independent travel time, distance, and evacuation capacity. Bidirectional streets are represented by reciprocal directed rows.

⌘

Algorithmic methods

Dijkstra heap and array, admissible A*, BFS/DFS, Kruskal with disjoint sets, Edmonds–Karp maximum flow, and Bellman–Ford in an isolated negative-weight lab.

▤

Layered application

Pure Python algorithms are coordinated by services, persisted through a centralized SQLite layer, exposed as Flask JSON APIs, and visualized with plain HTML, CSS, JavaScript, and SVG.

Complexity reference

Asymptotic time bounds shown alongside measured Python benchmark results.

Simulation limitations

This project has no live emergency dispatch, traffic feed, mapping service, or external data connection. The schematic map and all operational records are simulated. The hospital allocation heuristic is greedy and does not guarantee a globally optimal multi-incident assignment. Road-capacity flow results are theoretical throughput for a configured period, not operational safety guidance.
